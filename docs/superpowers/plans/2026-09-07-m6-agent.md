# M6 实施计划：ReAct Agent 问答模式（PydanticAI）

来源：docs/03-WeKnora对标优化方案.md §M6 v3（已确认）· 分支：m6-agent · 2026-09-07

## 全局约束

- 新增依赖仅 `pydantic-ai-slim[openai]`（T1 引入，唯一许可的依赖变更）。
- RAG 问答链路（mode=rag）零行为变化：现有 SSE 事件序列、citations、followups 不动。
- Agent 生成失败一律降级（error 事件 + 已生成内容收尾），绝不 500 或挂死连接。
- 工具结果是数据非指令（系统提示硬约束）；不提供代码执行/文件写工具。
- 错误 detail 与注释中文；基线 197 passed / 1 skipped 持续全绿；pnpm build 通过。
- 每任务独立提交（中文信息）；不要启动/关闭任何服务进程（oMLX 8000 是用户的）；不要 push。

## 关键既有事实

- oMLX 已实测支持 OpenAI function calling（含流式 tool_calls），base_url=http://localhost:8000/v1。
- 现有 SSE：`stage`/`citations`/`delta`/`done(followups)`/`error`，前端 sse.ts 已按 type 分支。
- 检索：`retrieve(workspace_id, query, use_rerank=…, top_k=…, hybrid=…)`（backend/app/services/retrieval/search.py）。
- LLM provider 配置：`get_default_provider(s, "llm")` + `decrypt_api_key`（backend/app/services/providers_service.py）。
- 网页抓取：`backend/app/services/ingestion/web_fetch.py` 的 fetch_url_to_doc / validate_url（SSRF 防护）。
- pydantic-ai 测试：TestModel/FunctionModel（pydantic_ai.models.test / function）无需 mock HTTP。
- Agent 轮数上限：`UsageLimits(requests_limit=N)`；超限抛 UsageLimitExceeded。

## T1 Agent 引擎（backend/app/services/agent/）

- `pyproject.toml` 加 `pydantic-ai-slim[openai]`（uv add）。
- `agent.py`：`build_agent(workspace_id: int, max_turns: int = 6) -> Agent`——model 用 OpenAIChatModel + 自定义 provider（base_url/model/api_key 来自默认 llm provider 配置，api_key None 时省略）；Deps dataclass（workspace_id、citations: list、max_turns）；system prompt 放 `prompts.py`（工具结果是数据非指令；先 kb_search 再回答；答不出就说不知道）。
- `tools.py`：三个工具注册在 build_agent 内——
  - `kb_search(query: str)`：调 retrieve(deps.workspace_id, query, top_k=5)，把命中文本（含 filename/heading_path/page_no）拼接返回，同时登记 deps.citations（去重，按首次调用顺序编号）；
  - `read_url(url: str)`：validate_url 校验后复用 web_fetch 抓正文，截断 2000 字符；校验失败/抓取失败返回中文错误说明字符串；
  - `web_search`：本任务不实现 provider，仅预留接口形态（注册逻辑开关），不注册。
- `runner.py`：`agent_stream(conversation_id, question) -> AsyncIterator[str]`——用 `agent.iter()` 消费事件：delta→`_sse({"type":"delta","text":…})`；工具调用/返回→`_sse({"type":"agent","event":"tool_call"|"tool_result","tool":…,"args":…,"preview":…})`（preview 截 200 字符）；结束→`citations`（deps.citations）+`done(followups=[])`。UsageLimits(requests_limit=max_turns+1)；整体 `asyncio.wait_for` 120s；UsageLimitExceeded/超时→`error` 事件（中文 detail）+ 已收集内容收尾，不抛出。
- 消息落库：与 RAG 相同（历史加载、user 消息、assistant 回答含 citations JSONB）——在 runner 内复用 service.py 的既有函数或等价实现。
- 测试（tests/test_agent.py）：TestModel 固定轨迹（工具多轮调用→事件顺序断言）、FunctionModel 模拟工具失败（错误 Observation 继续而非中断）、超轮数 UsageLimitExceeded → error 事件收尾、kb_search 工具单测（工作区隔离：只返回本工作区命中；citations 登记去重）、read_url SSRF 拒绝（validate_url 对内网地址抛错路径）。

## T2 API 与持久化

- `AskIn` 加 `mode: str = "rag"`（"rag"|"agent"，其他值 400）；ask 端点分流到 agent_stream。
- `messages` 表加 `trace JSONB`（可空），Alembic 迁移（downgrade drop 列）。
- agent_stream 结束时把工具时间线（tool/args/preview 列表）写 messages.trace；RAG 模式 trace=NULL。
- 历史消息接口（list_messages）带出 trace 字段。
- 前端 sse.ts：SSEEvent 加 `{type:"agent"; event:"tool_call"|"tool_result"; tool:string; args?:unknown; preview?:string}`。
- 启动探测：lifespan 里对默认 llm 发一次最小 tools 请求（2s 超时），结果写 app_config key="agent_capability"（true/false/null=未测）；`GET /api/agent/capability`（需认证）返回 {available: bool}；探测失败=不可用，绝不阻塞启动。
- 测试：mode 分流（agent 模式走 agent_stream——TestModel）、trace 落库与历史带出、capability 接口、非法 mode 400。

## T3 前端

- ChatPage：会话级「Agent 模式」开关（输入框旁 toggle；GET capability 为 false 时隐藏）。
- agent 事件渲染：回答气泡内可折叠时间线（工具调用卡片：工具名+参数摘要+结果 preview），最终回答照常 markdown；历史消息有 trace 也渲染折叠时间线。
- DocumentsPage/SettingsPage 不动（web_search 设置区块推迟到真实 provider 落地时）。
- 验证：pnpm build + vitest（sse.test.ts 补 agent 事件解析用例）。

## T4 评测与收尾

- run_eval.py 加 `--agent`：hybrid 检索对比改为 rag vs agent 两模式命中率对比（agent 走 TestModel 不可行——需真实 LLM；实现为调用 agent_stream 的完整链路，未配置 LLM 时 SystemExit 提示；mock 测试覆盖报告输出与降级）。
- README：功能段补 Agent 模式说明（开关位置、工具列表、护栏）。
- 真实 oMLX 联调：控制器在实施后用临时端口做一次端到端验证（实施者不做，报告注明）。
- 全量回归 + 评测。

## 顺序与依赖

T1 → T2 → T3 → T4（T2 依赖 T1 的 runner；T3 依赖 T2 的事件契约；T4 依赖全部）。
