### Task 2: 混合检索（jieba + tsvector + RRF）

**Files:**
- Create: `backend/alembic/versions/xxxx_add_chunks_fts.py`（autogenerate 后手工补）、`backend/app/services/ingestion/backfill_fts.py`、`backend/tests/test_hybrid_search.py`
- Modify: `backend/pyproject.toml`（+jieba）、`backend/app/services/ingestion/pipeline.py`（ingest 写 fts）、`backend/app/services/retrieval/search.py`（双路召回 + RRF）、`backend/app/api/settings.py`（workspace params 增 `use_hybrid`）、`backend/tests/evaluation/run_eval.py`（--no-hybrid 参数透传）

**Interfaces:**
- Produces:
  - 迁移：`ALTER TABLE chunks ADD COLUMN fts tsvector`；`CREATE INDEX idx_chunks_fts ON chunks USING GIN (fts)`；downgrade 对称。**迁移不做数据回填**（jieba 是 Python）
  - `def tokenize_for_fts(text: str) -> str`：jieba.lcut 后以空格 join（过滤空白 token）——写入与查询两侧共用
  - ingest：插入 Chunk 时 `fts=to_tsvector('simple', :tokens)`（SQL 表达式 `func.to_tsvector('simple', tokenize_for_fts(content))`）
  - `python -m app.services.ingestion.backfill_fts`：分批（id keyset，批 500）为 fts IS NULL 的 chunk 回填；幂等；打印回填数量
  - search 增参 `hybrid: bool = True`：True 时并行做 FTS 召回（`websearch_to_tsquery('simple', :tokens)`，ts_rank 排序，top_k）——**各自独立取 top_k 后 RRF 融合**：`rrf_score = Σ 1/(60 + rank_i)`（向量路 rank 从 1 计、FTS 路 rank 从 1 计，缺席不计）；按 rrf_score 降序取 top_k；score 字段输出 rrf_score（仅用于排序，前端不展示具体值也无妨）；hybrid=False 或 FTS 异常 → 纯向量原逻辑
  - retrieve 透传 hybrid；workspace params 增 `use_hybrid: bool = True`（WorkspaceSettingsIn + RETRIEVAL_DEFAULTS）；ask_stream 读取合并（chat/service.py ws_params 处）
  - run_eval 增 `--no-hybrid`：search(..., hybrid=False)
- 测试：tokenize 单测；hybrid 检索——造文档（关键词明确命中 FTS 路、向量路难命中的用例：fake embedding 下用语义无关但词面匹配的 query）验证 hybrid 命中优于纯向量；fts NULL 的旧 chunk 不进 FTS 路但不报错；FTS 异常降级（可 monkeypatch）；backfill 幂等

- [ ] Step 2: 实现 tokenize/ingest 写入/双路召回/RRF/backfill/参数接线
